# 体液免疫：对齐新版细胞免疫的交互改版设计

## 目标

将体液免疫模型改造成与新版细胞免疫一致的教学交互体验，同时保留体液免疫自身的生物学过程。两套模型应具有相同的信息层级、控制方式、阶段反馈和视觉节奏，学生在两者之间切换时不需要重新学习操作方法。

成功标准：

- 体液免疫采用与细胞免疫相同的七阶段流程结构和三项解释结构。
- 学生可以独立选择抗原特异性和 B 细胞受体特异性，并观察匹配与不匹配的不同结果。
- 不匹配、上游受阻和正常推进具有明确且不同的视觉与文字反馈。
- 初次免疫、记忆匹配的二次免疫、受阻实验、曲线对比和时间轴控制继续可用。
- 桌面端与移动端均保持清晰、可操作，并延续现有无障碍支持。

## 设计原则与边界

采用“同构但不强行共用组件”的方式。体液免疫页面沿用细胞免疫的信息架构和交互语言，但继续使用独立的组件、类型与模拟函数。这能保持两套体验一致，也避免把两种不同的免疫过程塞进复杂的通用抽象。

本次不修改模型首页、细胞免疫模型、导航结构或其他四个生物模型，也不引入持久化数据和新的外部服务。

## 七阶段教学流程

体液免疫时间轴调整为以下七个阶段：

1. 抗原呈递：抗原进入体内后，抗原呈递细胞处理并展示抗原信息。
2. 辅助性 T 细胞活化：辅助性 T 细胞识别呈递信息并提供协同信号。
3. B 细胞活化：BCR 与抗原特异性匹配的 B 细胞获得有效帮助。
4. 克隆增殖：活化的 B 细胞选择性扩增，后代保持相同特异性。
5. 分化：B 细胞后代分化为浆细胞和记忆 B 细胞。
6. 抗体产生与结合：浆细胞分泌特异性抗体，抗体与匹配抗原结合并促进后续清除。
7. 免疫记忆：保留记忆 B 细胞，为同种抗原再次进入提供更快、更强且更持久的反应。

“抗原进入”在场景起点和第一阶段说明中表达，不再单独占用时间轴节点。“促进清除”作为抗体结合的结果表达，不再单独占用节点。

## 控制区

控制区按照细胞免疫的顺序和层级组织：

1. 抗原类型：抗原 A、抗原 B。
2. B 细胞受体：BCR A、BCR B。
3. 暴露次数：初次免疫、二次免疫。
4. 既往记忆特异性：记忆 A、记忆 B。
5. 实验干预：正常流程、抗原呈递受阻、辅助性 T 细胞受阻、缺少 B 细胞。

任一实验条件变化都会停止播放并将教学时间归零。速度、播放、暂停、上一步、下一步、重置和时间轴拖动继续保留。

## 特异性匹配规则

抗原类型与 BCR 特异性独立设置：

- 当抗原与 BCR 匹配且没有实验干预时，反应正常推进至抗体结合和记忆形成。
- 当抗原与 BCR 不匹配时，流程推进到“B 细胞活化”阶段后停止。页面显示“未匹配”，而不是“受阻”；浆细胞、抗体和新记忆 B 细胞均保持为零，抗原不因本模型中的特异性抗体而下降。
- “缺少 B 细胞”是实验干预，表示没有执行该环节的细胞；它与“存在 B 细胞但 BCR 不匹配”使用不同解释。
- 记忆匹配仅在二次免疫、既往记忆特异性与当前抗原一致、BCR 也与当前抗原一致且流程没有受阻时生效。
- 记忆不匹配时按初次免疫反应展示，不获得二次反应优势。

## 页面与场景结构

页面继续使用“过程场景 + 曲线 + 当前解释 + 控制区”的整体结构，并将过程场景调整为四个聚焦区域：

1. 辅助性 T 细胞：显示等待呈递信息或提供帮助信号。
2. B 细胞：显示 BCR A/B、等待活化、已活化、未匹配或受阻状态。
3. 克隆与分化：用粒子数量和标签展示 B 细胞后代、浆细胞与记忆 B 细胞的形成。
4. 抗体—抗原结合：展示抗体移动、特异性结合、未结合以及抗原相对量下降。

播放时才运行动画，暂停时粒子保持静止。减少动态效果的系统偏好继续受到尊重。抗原 A 与 B 继续同时使用文字和不同形状表示，不能只依赖颜色区分。

## 阶段解释与状态反馈

解释卡统一使用三项结构：

- 发生了什么。
- 为什么能识别。
- 结果是什么。

状态标题分为三类：

- 正常阶段：显示当前七阶段标题。
- 上游干预：显示“过程受阻”，说明缺少的条件和下游后果。
- BCR 不匹配：显示“未匹配”，说明 BCR 只能识别相应抗原，并明确不会形成浆细胞、特异性抗体或新记忆。

实时数量单独显示浆细胞数、记忆 B 细胞数、抗体相对量与抗原相对量。无障碍实时播报只在阶段或受阻状态发生变化时更新，避免拖动时间轴时连续播报数值。

## 曲线行为

曲线继续同时展示抗体相对量和抗原相对量：

- 正常初次反应：抗体延迟上升，抗原随后下降。
- 记忆匹配的二次反应：抗体更早、更高且维持更久，并叠加初次反应虚线作为对照。
- 记忆不匹配：按初次反应绘制，不显示二次优势说明。
- BCR 不匹配或任一阻断性干预：抗体维持为零，抗原不因该体液免疫反应下降，不显示初次反应对照虚线。

## 状态与组件边界

- `HumoralImmunityLab` 管理设置、教学时间、播放状态、速度、阶段解释选择和控制区事件。
- `simulation` 根据时间与设置生成唯一快照，包括当前阶段、停止阶段、记忆是否匹配、细胞数量、抗体量、抗原量和结合状态。
- `HumoralProcessView` 只根据设置和快照渲染七阶段流程与四区场景，不自行推导免疫结果。
- `AntibodyChart` 只根据设置、快照和时间绘制当前曲线及必要的初次反应对照。

所有生物学分支都在模拟层决定，避免场景、解释卡和曲线对同一条件给出不一致结果。

## 异常与边界状态

- 教学时间始终限制在模拟总时长内。
- 播放到末尾自动停止；在末尾再次播放时从头开始。
- 切换设置立即暂停并归零，防止旧条件的时间状态污染新实验。
- 不匹配或受阻后，即使时间轴继续拖到末尾，快照阶段也保持在相应停止点。
- 在流程尚未到达结合阶段前，即使抗原与 BCR 匹配，也显示“等待识别或结合”，不能提前显示失败。

## 测试与验证

采用测试驱动实现，先写会失败的行为测试，再修改模型：

- 七阶段流程及首尾节点正确呈现。
- BCR 与抗原匹配时正常形成浆细胞、抗体和记忆。
- BCR 不匹配时停在 B 细胞活化阶段，并显示“未匹配”。
- 不匹配与“缺少 B 细胞”使用不同解释。
- 受阻状态不显示二次反应对照，抗体保持为零。
- 记忆匹配的二次反应显示更快、更强、更持久及初次反应虚线。
- 设置变化会暂停并归零。
- 阶段播报不会包含连续变化的数量。
- 桌面端七列流程、移动端单列流程和减少动态效果规则存在。

完成单元与组件测试后，运行完整测试、代码检查和生产构建，并在桌面及移动尺寸下检查布局、状态文案、时间轴推进和匹配/不匹配场景。
